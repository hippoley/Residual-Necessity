# Node Valuation

Residual Necessity is a vehicle, not a destination.

The project should continuously move toward the highest-value external node where existing work can compound into durable identity, dependency, citation, governance influence, or standards position.

## Current node stack

### N0 — standalone gate/framework
Value: low.

A self-contained pre-action gate is crowded and easy to absorb into larger agent runtimes.

Do not optimize for framework surface area.

### N1 — residual-necessity runtime primitive
Value: medium.

Distinct question:
> What current violated condition still exists that makes any further state transition necessary?

Useful, but adjacent work such as abstention benchmarks and action-repair systems substantially overlaps stale/no-op/retry behavior.

### N2 — bounded predicate completeness / negative-evidence authority
Value: high.

Core question:
> When may absence of an observation soundly support FALSE for a specific predicate, target, and revision?

This is model-external, reusable across runtimes, and directly affects false abstention.

Current implementation:
- predicate-scoped completeness witness;
- target/revision binding;
- explicit completeness basis;
- inspectable evidence reference;
- FALSE without a matching witness remains unresolved.

### N3 — standards / conformance node
Value: highest currently observed.

Candidate external surface:
Agent Definition Language Runtime Protocol.

ADL already defines signed runtime enforcement evidence and reserves a completeness/witness tier. Its current reserved completeness concerns record omission detection. Residual-Necessity has surfaced a distinct downstream question: record completeness does not automatically imply proposition-level completeness.

The high-value move is therefore not to create a parallel standard. It is to test whether this distinction belongs in:
- ADL Runtime Protocol clarification;
- a future RFC;
- conformance vectors;
- an evidence-provider profile;
- or explicitly outside ADL.

If accepted as an open gap, Residual-Necessity should reposition as:
1. reference implementation;
2. conformance probe;
3. falsification corpus;
4. interoperability adapter.

## Evidence supporting the pivot

- ExecSurface independently qualified a Residual-Necessity workload run as a genuine external real-workload evidence record under its own preregistered protocol.
- Real downstream evidence consumption exposed the difference between successful workload execution and sufficient observation authority.
- TwinCheck substantially overlaps evidence-grounded action repair, stale arguments, retries, and no-op behavior; those cannot remain the primary novelty claim.
- ADL Runtime Protocol explicitly has an open completeness/witness design surface, but its current reserved text is record-level rather than proposition-level completeness.

## Pivot rules

Move upward when:
- an external standard/spec has an explicit open seam;
- our existing evidence gives us a non-speculative contribution;
- entering that seam creates a durable public contribution history;
- the node is harder for a larger model to absorb than a standalone implementation.

Move sideways when:
- another project owns the broader primitive but lacks our narrow evidence semantics;
- interoperability can create mutual dependency faster than competition.

Move downstream when:
- standards scope intentionally excludes the concept;
- conformance/value can still be demonstrated as implementation infrastructure.

Kill or upstream when:
- a mature adopted system already owns scoped proposition-level completeness/negative authority;
- real paired evaluation shows no value beyond generic HOLD/repair/abstention;
- the project only survives by renaming existing concepts.

## Current decision

As of 2026-10-08:

> Prioritize the ADL standards/conformance node over standalone framework expansion.

Do not add broad framework features unless they directly support:
- a conformance vector;
- a standards/RFC question;
- an external consumer;
- or a measurable stale/partial-fix/retry falsification case.

This file should be updated whenever a materially higher-value node appears.
